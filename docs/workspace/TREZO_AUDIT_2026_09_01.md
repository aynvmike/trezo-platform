## 1. Corrections to the audit brief itself

Four premises in the brief did not survive contact with the code. Recording them so nobody re-derives from the brief:

1. **There is no "0.5 R:R floor" constant.** The floor is per-book `bot_settings.min_reward_risk` (live values: signal user `cf1b04…` = 0.4, the two executing books = 0.5, a fourth stale row = 1.0; DB/seed default 1.5, clamp 0.3–3.0). The "0.5" in the brief is the **0.5×ATR stop-noise multiplier** at `risk_manager.py:1218`. The floor kills at `sizing.py:183` (called from trade_execution), not in risk_manager.
2. **`options_positions` is not empty.** It holds 242 rows, 2 currently open — but ~232 of the 242 are import→close→re-import churn (§2.3). The `broker_truth.py:19-21` "holds ZERO open rows" post-mortem is a stale docstring. The real option book (7 live legs) is in `paper_positions asset_type='option'`, as the brief says — the situation is a live **split-brain ledger**, worse than an empty table.
3. **Net 2's premise is inverted.** Equities are not "approving nothing" — risk_manager approves them (119 stock approves in the last ~8h) and they die at execution sizing. Net 2 counts risk-gate output, so it was structurally guaranteed silent (§2.6).
4. **The phantom P&L is bigger than briefed.** Not ~−$5.8k/8×: the loop ran through 8/29 16:07 (the strict-read fix landed 8/29 21:06 UTC, after the last phantom close). 75k book: 10 proven phantom rows −$7,462.53 + 1 ambiguous row −$182.61 = 11 rows / −$7,645.14 booked. Plus primary 3 rows −$13.12 and the 25k book 3 rows −$173.74.

### Firing right now

**2.1 ✔ The balance reconciler overwrites every book's cash ledger with the PRIMARY's broker cash — live, proven twice today.**
`reconcile_account_balances_all_users` (`agents/app/paper/stocks_reconcile.py:527-598`) loops all `paper_accounts` rows with **no `bind_for_user`** (its sibling stock reconciler binds; this one never did). With no OAuth token anywhere, `get_account()` at :571 resolves unbound → primary credentials, and it patches **that user's** `current_cash_usd` on drift ≥ $1. Cadence ~hourly (60×60s ticks) plus ~2 min after every restart and every integrity sweep. **Live proof:** all three books' `current_cash_usd` read identical to the cent — 1247.01 at one auditor's read, 1276.89 twenty minutes later at the verifier's, i.e. the value *changed while staying cloned*, with `updated_at` stamps 3–4 seconds apart (15:44:08/:11/:15 UTC today). That number feeds `_execute_internal` equity, the per-coin cap's `_account_equity`, and `effective_equity`'s ledger fallback — cross-book sizing contamination on a live cadence. It is also the prime suspect for §2.7.

**2.2 ✔ Open item (a), quantified: the equity lane is dead at execution, and the mechanism is a cross-book settings leak.**
Count (rolling; agent_messages purges at 48h): **126 R:R-floor rejections at 15:30Z, 134 at 15:50Z re-count, ~101/full trading day. Every single one parses "Reward:risk 0.4 below your 0.5 floor."** By book: 75k=103, 25k=31. 08-31 symbols: WMT 14, INTC 14, AAPL 12, RBLX 11, PYPL 11, SOXL 9, QQQ 7, NVDA 6, TSLA 5, TQQQ 4, more — Mike's 6-for-6 report confirmed symbol-for-symbol. Mechanism, verified line-by-line and against stored approvals: signals carry user `cf1b04…`; `risk_manager.py:458` loads *that* row (floor **0.4**); the learned-target shrinker (`:1180-1197`) caps target at 0.006 ("learned from 6–7 recent trades" — and 0.006 is also the `TREZO_TARGET_MIN_PCT` clamp); the harmonizer (`:1258-1271`) sets stop = 0.006/0.4 = **1.5%** (the literal "stop 1.5% keeps R:R >= 0.4" appears in stored approval reasons); the fan-out then binds each executing book and `sizing.py:177-178`'s bare `get_bot_settings()` resolves to the **bound book's** row (floor **0.5**): round(0.006/0.015,2)=0.40 < 0.5, deterministic rejection, every time. Only scalp-geometry equities survived (XLK, XLF ×2, BAC); crypto is exempt by design. Note the harmonizer emits geometry *exactly at* its floor, so any executing book with a floor even 0.01 above the signal user's rejects 100%. There is also a **feedback trap**: zero fills means the learned 0.6% target can never recover. Which control yields is HELD FOR MIKE (§5.a) — but the two-different-settings-rows shape is a rule-2 defect regardless.

### Armed — wrong-account order paths waiting on a trigger

All of these share one root: an unbound broker call in multi-account mode resolves to the **primary** account (`alpaca._headers → current_account → primary_account`). The 2026-08-11 fix bound trade_execution, position_monitor's row loop, and the wheel auto-fire — these call sites never adopted it.

**2.7 ✔ rank 5 — Options harvest exits submit unbound for every book's rows.** The hourly re-score inside `_settle_expired` selects ALL users' open single-leg option rows (no user filter, `options_scanner.py:1194-1204`) and fires real `submit_option_order` exits at :1487-1491 with no token, no binding, and — unlike every entry lane — **no `_user_halted` check**. Correction from verification: the row bookkeeping applies only to *partial* step-down exits; a full exit leaves the row open for the (also wrong-account) reconcile pass.

**2.8 ✔ rank 4 — Gap-check and pre-break review cancel and rewrite the PRIMARY's exit legs using other books' rows.** `_pre_break_review` and `_gap_check_open_bell` run at tick start before any binding, iterate all books' `paper_positions`, and call `resync_alpaca_legs`, which cancels open orders and submits an OCO unbound. Live-armed, trigger is a market event.
